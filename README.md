# 轻生活微信小程序

轻生活用户体验数字化系统的原生微信小程序。项目在现有轻生活小程序能力和同一 AppID 基础上，重新实现轻体营、每日记录、内容、收藏及轻友社区体验，不嵌入 H5。

当前版本：`V1.2 Demo`。短信验证码、订阅消息和新系统写入能力在本地模拟；正式版将接入真实服务。

## 本版边界

- 五频道：首页 / 轻体营 / 内容 / 轻友 / 我的。
- 轻体营、报名、签到、复食、14/21 日计划、新动态、举报、手机号验证码和订阅消息使用本地演示状态。
- 验证码固定为 `123456`，不会真实发送短信。
- 订阅消息只模拟授权状态，不调用真实订阅接口。
- 文章、收藏、旧动态优先调用旧服务；接口不可用时自动回退到明确标注的演示内容。
- 旧动态只读；新动态只写本地新系统演示状态，不调用旧动态写接口。

## 打开方式

使用微信开发者工具导入当前目录。项目配置已经沿用现有轻生活小程序 AppID。

### 更换设备后继续开发

1. 安装 Git、Node.js 和微信开发者工具。
2. 克隆私有 GitHub 仓库并进入项目目录。
3. 执行 `npm test`，确认领域逻辑和静态契约测试通过。
4. 在微信开发者工具中导入项目根目录，选择“不使用云服务”。
5. 使用已加入该 AppID 开发者成员列表的微信账号登录开发者工具。

`project.private.config.json` 属于设备本地配置，不进入 Git。微信开发者工具会在新设备首次导入时重新生成该文件。

## 开发与版本管理

```bash
npm test
git pull --rebase
git add -A
git commit -m "描述本次修改"
git push
```

建议每次开始开发前先同步远端；完成功能并通过测试后再提交、推送，避免设备之间产生未同步分支。

## 验收建议

1. 在“我的”切换新访客、轻体营中、复食第3天、习惯期。
2. 检查首页主任务是否随阶段变化。
3. 完成报名、签到、私人记录、整理为公开副本、举报等流程。
4. 在内容与历史动态页面观察“现有服务 / 演示数据”来源标识。
5. 重置演示状态后确认所有本地流程恢复初始值。
