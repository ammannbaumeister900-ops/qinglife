# 轻生活微信小程序

轻生活数字化运营系统的原生微信小程序端，包含普通轻友页面和内部工作人员移动工作台。

当前版本：`V1.3.x 隔离测试版`。主要业务已具备测试环境 API 接入能力，同时保留本地 Demo 和旧内容只读兼容逻辑；是否调用真实业务接口由运行配置决定。

界面基线：`轻生活前端产品设计规范 V1.1`。全部 9 个路由页统一使用“呼吸的纸面”视觉语言、动态微信胶囊安全区、V1.1 Design Tokens 与一致的加载/空白/失败反馈。

## 本版边界

- 四频道：首页 / 轻体营 / 轻读 / 我的。我的底部保留历史打卡文字入口。
- 轻体营、报名、签到、复食和工作人员工作台可接入测试环境 API；未配置业务地址时使用本地演示状态。
- 验证码固定为 `123456`，不会真实发送短信。
- 订阅消息只模拟授权状态，不调用真实订阅接口。
- 文章、收藏、历史打卡调用旧服务；接口不可用时显示错误并允许重试，不替换为演示数据。
- 旧动态只读分页，保留图片与原始时间；不提供新的发布、点赞、评论，不调用旧动态写接口。历史本地状态未删除。
- `data/demo.js` 同时提供正常、空白、失败和活动状态演示数据，供页面状态自测使用。

## 运行环境契约

- `demo` 可不配置后端，并仅允许通过本地存储覆盖到 HTTPS 或 `127.0.0.1` 调试地址；所有本地保存提示都会明确标为演示记录。
- `staging` 使用 `config/runtime.js` 中固定的 HTTPS `businessBaseUrl`，忽略本地存储覆盖。
- `production` 必须配置固定 HTTPS `businessBaseUrl`，且其 origin 必须列入 `allowedBusinessOrigins`；缺失或不匹配时页面明确失败，不回退 Demo。
- Legacy 使用独立 `qinglife_legacy_token`，不读取当前业务 token；地址、启用状态和写权限均显式配置，默认禁止 Legacy 写入。

## 打开方式

使用微信开发者工具导入当前目录。项目配置已经沿用现有轻生活小程序 AppID。

### 更换设备后继续开发

1. 安装 Git、Node.js 和微信开发者工具。
2. 克隆仓库并进入 `apps/miniapp` 目录。
3. 执行 `npm test`，确认领域逻辑和静态契约测试通过。
4. 在微信开发者工具中导入项目根目录，选择“不使用云服务”。
5. 使用已加入该 AppID 开发者成员列表的微信账号登录开发者工具。

`project.private.config.json` 属于设备本地配置，不进入 Git。微信开发者工具会在新设备首次导入时重新生成该文件。

## 开发与版本管理

```bash
npm test
git pull --rebase
git add -A
git commit -m "描述本次修改"
git push
```

建议每次开始开发前先同步远端；完成功能并通过测试后再提交、推送，避免设备之间产生未同步分支。

## 验收建议

1. 运行 npm test，覆盖阶段优先级、当天到场、无预选记录及真实接口分页失败。
2. 在微信开发者工具使用不同阶段样例检查四导航、两步报名、私人记录及历史打卡。
3. 历史打卡须用有效微信登录实测真实正文、图片、原日期、后续分页和失败重试。
4. 验收 iOS/Android 字号、胶囊、安全区与按钮，代码测试不替代真机验收。
5. 报名/回顾/身份/订阅仍为本机演示，不能作为正式履约与身份校验。
