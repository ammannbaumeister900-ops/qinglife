# 老带新与本期轻友登记分享 R10

## 产品规则

- 老带新先记录推荐归属与报名结果，不发卡次、优惠或现金奖励。
- 我的 → 邀请轻友 → 选择开放报名的期次 → 准备邀请 → 微信原生分享给朋友或微信群。沿用现有资格：成年、本人有已结束期次的确认报名及实际到场记录。
- 受邀者登录后经邀请提交报名，本期推荐人按邀请归属记录；首次推荐关系只在没有既往报名、没有首次推荐人时建立，不覆盖已有关系，不给自己归属自己。
- 我的邀请记录只返回自己推荐的报名、小名、期次、报名状态与时间，最多最近 100 条。不提供受邀者手机号、真实姓名、健康登记、付款或卡次信息。
- 移动工作台 → 分享轻友登记表（新） → 选择期次 → 准备登记表 → 分享到微信群。由运营人员自己选择群并发送。
- 分享使用现有工作人员 enabled 与 can_operate 权限；拥有收款权限不等于拥有分享权限。分享操作不扩大健康档案查看授权。
- 工作台可选择尚未结束的已发布期次（open / in_progress），开课前也可填写；登记开放到期次截止日当天 24 点，取消或结束后关闭。报名截止时间不影响本期登记补填。
- 轻友点卡片进入小程序，由现有微信登录确定本人账号。期次从服务端生成的分享码解析，客户端不能指定档案归属者或替换期次。单独填写登记不等于提交轻体营报名。
- 每次新提交追加本人档案历史，显示期次；请求重试不重复新增，已成功请求在期次结束后仍可重放。原有日常登记与历史记录保留，无期次显示“日常登记”。
- 每个账号、每个分享码隔离草稿；登录账号变化时清空当前表单并重新读取本人的档案。历史修改沿用原 48 小时规则，修改不能改变所属期次。

## 数据与接口

- 新增 V1_4_12__assessment_session_invitation.sql，仅增加可空关联及邀请用途；旧邀请默认 registration，旧登记保持无期次。不修改既有资金规则或发放奖励。
- ql_invitation 复用分享码，区分 registration / assessment；运营生成的登记码记录 created_by_sys_user_id，owner_customer_id 为空，不建立运营人员的推荐关系。
- ql_friend_assessment 新增 session_id / invitation_code 关联，历史输出只返回期次，不返回分享码。
- GET /app/qinglife/me/referrals：本人推荐报名记录，需小程序登录。
- GET /app/qinglife/friend/assessment-invitations/{code}：登录后解析登记上下文。
- GET /app/qinglife/staff/assessment-sessions：运营可分享期次，返回期次基础信息。
- POST /app/qinglife/staff/sessions/{id}/assessment-invitations：运营生成登记分享路径。
- POST /app/qinglife/friend/assessments：新增可选 invitationCode，归属依据登录令牌。PUT 历史修改保留已有上下文。
- 原报名接口继续校验活动与邀请匹配，仅接受 registration 用途。登记码不能用于活动邀请或报名。
- 管理后台轻友档案历次登记显示对应期次；报名列表显示本期推荐人。
