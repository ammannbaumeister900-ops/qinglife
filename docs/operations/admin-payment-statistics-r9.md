# 统计期次快捷筛选与统一付款 R9

日期：2026-10-04。基于现有隔离工作区保留 R4–R8 未提交改动。本次代码未提交、推送；生产未修改。

## 当前行为

- 数据统计增加“按期次”：日期取该期的 registration_open_at 所在日期至 end_date，包含结束当天。它是时间范围快捷方式，指标仍按登记提交时间和轻友建档时间统计，不额外限定报名参与人。没有配置报名开始日、或开始日晚于课程结束日时，期次不可选择并提示补齐配置；不猜测起点。
- 报名与付款只展示一列付款状态。报名未确认时只开放确认报名；多人订单要全部确认后才能确认付款。
- 新“确认付款”表单要求选择实际付款方式和填写金额。现金在同一个后端事务中确认最终金额与登记收款，失败一起回滚。卡次选账户、次数，默认 1 次及最新可用账户；沿用发起人账户归属与原不可变流水，不创建现金收款记录。
- 原来的结算、收款事实及审计记录保留；旧接口仍兼容工作人员端。后台新的操作入口调用 /life/registration/{id}/payment-confirmation，继续要求 life:registration:payment。
- 历史已确认但未收款的现金记录按原金额付款，不允许在收款时悄悄改金额或结算轮次。修改需先撤销原金额确认；已付款先撤销付款登记。撤销金额及卡次仍使用原独立撤销权限。
- 所有行内操作都在“操作”列，主要按钮随当前状态显示；“更多”只含当前可执行的编辑、取消或撤销操作。已取消行无操作按钮。付款筛选“已完成”同时包含现金已付款与卡次已抵扣。

## 17 天的来源

已只读核实隔离公开 API：第 10001 期 startDate=2026-10-01、endDate=2026-10-17、days 数组长度=17；第 10002 期 10-01 至 10-03，为 3 天。

QlSessionServiceImpl.syncSessionDays 在开始至结束日期逐日生成活动日，含首尾；公开 API 读取未取消的 ql_session_day，前端详情显示 activity.days.length。天数不包含报名等待期，也不是倒计时。没有调整这两个期次的实际日期。

小程序源码把写死的“三天的节奏”改为“本期的节奏”，日序号支持第 4 天以后。此小程序展示修正尚未重新上传微信预览；本次后台发布无需修改微信包即可生效。
