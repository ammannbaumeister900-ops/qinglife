# 后台卡次与账号页面权限 R8

日期：2026-10-04。代码位于现有工作区 \qinglife-employee-health-access，保留此前未提交的 R4–R7 改动。代码未提交、未推送；已上传并更新至获准的隔离验收环境。生产未变更。

## 使用变化

1. 卡次开户：原“核验依据”改为选填“备注”；增加选填单张图片，支持 JPG / PNG、2MB 以内。图片随确认开户保存，列表中的“图片”入口通过卡次查询权限加载，不生成公开链接。取消选择不会产生孤立上传文件。
2. 报名与付款：选择“消耗卡次”时隐藏最终金额，接口沿用现金金额为 0 的既有结算规则；使用卡次默认 1。按账户创建时间从新到旧，默认选取已生效、在有效期内且余额足够的账户，没有可用账户时保留未选状态并要求选择。多人订单使用发起人的账户，后台单人报名使用实际参与人的账户。归属由后端根据报名记录确定。现金结算仍显示并要求填写最终金额；确认结算仍不等于人工收款。
3. 调整卡次：可以同时修改次数和有效期，或次数保留 0 只修改日期。前后端均阻止截止日期早于开始日期；有效期调整保存前后日期、原因、操作者与时间。“记录”汇总次数流水和日期调整。旧客户端未传 changeValidity 时保留原有效期。
4. 权限管理 → 账号权限：列出所有未删除后台登录账号，包括停用账号；小程序轻友账号不属于此配置。可选择“沿用角色页面”或“按账号配置”。角色未授予的页面禁选；可勾选的是当前正常角色授权的业务页面，操作按钮和数据范围不新增权限。超级管理员保留所有页面。配置自己的账号时必须保留账号权限页面，避免失去管理入口。通用欢迎首页、个人中心、登录及错误页保留为公共路由。

取消业务页面会过滤菜单、路由及对应功能权限；旧 token 的接口调用也会重新检查当前账号配置。菜单在刷新页面后更新。角色后续撤销或停用时，账号配置不会恢复失去的权限。全部取消与“沿用角色”分别存储，规则修改保留独立审计记录。

卡次与报名弹窗使用轻量选项接口，避免要求用户同时打开其他业务页面。轻友选项只返回 ID、小名及已有姓名；期次只返回 ID、期数及名称；卡次选项只返回账户及余额有效期信息。选项数据仍要求账号现有角色具有对应查询权限。

## 验收顺序

1. 空备注、不选图片建立测试卡次；再创建带单图的测试卡次，打开图片检查。
2. 只延长有效期，检查剩余次数不变和记录中的前后日期；尝试结束日期早于开始日期，应拒绝保存。
3. 在待结算报名中切换“消耗卡次”，检查金额隐藏、次数为 1、最新可用账户默认选中；切回现金检查金额输入恢复。
4. 为测试后台账号只保留一个业务页面，刷新该账号，检查菜单和接口；恢复“沿用角色”后再次刷新。不要使用真实支付或生产账号做此验收。
