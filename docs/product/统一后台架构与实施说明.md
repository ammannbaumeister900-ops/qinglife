# 轻生活统一后台架构与实施说明 V1.2

更新时间：2026-09-03  
状态：本地代码与数据库迁移已完成第一轮实现；尚未执行阿里云生产库迁移与生产发布。

## 1. 统一架构结论

后续新增业务只进入现有若依后台代码：

- 管理端前端：`轻生活打卡小程序/后台代码/life-admin-ui`
- 统一业务 API：`轻生活打卡小程序/后台代码/life-admin-api`
- 统一业务事实：原 `lifestyle` 数据库内的 `ql_` 表
- 旧小程序服务：`lightlife-service` 暂时只保留微信登录、文章、收藏、历史动态等已有接口
- Redis：旧登录服务与统一业务 API 共用 `appToken:<token>`，统一 API 不延长 token 有效期

这不是重做一套新后台。旧的文章、收藏、动态、评论、标签、模板、联系信息、用户消息和若依账号权限继续使用；新增的轻友主档、期次、报名订单、线下付款、逐日签到、私人记录和内容治理统一进入 `ql_` 业务域。

## 2. 统一身份规则

- `ql_customer.id`：数据库物理主键，UUID，不暴露业务含义。
- `ql_customer.customer_no`：稳定轻友编号，面向运营与跨系统引用。
- 微信账号：通过 `ql_customer_identifier.legacy_app_user_id` 与一个轻友主档一对一绑定。
- 手机号：可更换，只是标识线索，不是主键。
- 身份证/护照：存在时作为强标识线索，保存归一化哈希和脱敏提示，不作为物理主键。
- 旧微信 token 首次访问新接口时，系统自动创建或找到唯一 `ql_customer`，以后复用同一主档。
- 购买人与参与人分离：一次 `ql_registration_batch` 是一张报名订单，购买人是 `submitted_by_customer_id`；每个实际参与人各有一条 `ql_registration`。

## 3. 本轮已补后台能力

### 小程序业务 API

统一前缀：`/app/qinglife`。除公开期次外，请求继续使用旧小程序的 `token` 请求头。

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| GET | `/sessions` | 可报名期次及逐日安排 |
| GET | `/me/overview` | 我的报名、付款、签到、私人记录、习惯计划概览 |
| POST | `/registrations` | 一名购买人替本人或多人报名，支持幂等请求号 |
| POST | `/attendance/check-in` | 已确认参与人在活动当天自助签到 |
| PUT | `/daily-records/today` | 新增或覆盖当天私人记录 |
| GET | `/daily-records` | 查询本人最近私人记录 |
| POST | `/habits` | 创建 14/21 日计划 |
| POST | `/posts/{publishId}/reports` | 举报旧动态或兼容动态 |
| PUT | `/subscriptions/{templateKey}` | 保存微信订阅偏好 |

私人记录固定写入 `visibility_scope=private`，不会因保存动作自动发布为动态。

### Web 管理后台

- 轻友档案：真实关联旧 `app_user_info`，展示微信昵称、头像、账号状态、最后登录，以及脱敏手机号/身份证提示。
- 期次管理：增加简介、公开地点、带领人、人工/自动确认、报名开放/截止时间、取消规则；按活动起止日期自动生成逐日记录。
- 报名与付款：展示订单号、购买人、实际参与人和订单应付金额；多人订单线下付款一次更新全部参与人，仍保留单人旧记录兼容入口。
- 活动签到：位于“活动运营”二级目录，按期次和活动日查看并由运营登记签到、迟到、缺席。
- 内容举报：位于“轻友动态”二级目录，查看动态举报并记录处理人、时间和处理结果。

后台导航仍保持两级，没有新增三级业务菜单。

## 4. 数据库迁移

执行顺序：

1. 原始 `lifestyle.sql`
2. `轻生活数据库升级V1.1/V1_1_0__qinglife_core.sql`
3. `V1_1_1__internal_roles.sql`
4. `V1_1_2__admin_modules.sql`
5. `V1_1_3__flatten_admin_navigation.sql`
6. `V1_2_0__miniapp_backend_support.sql`

V1.2 新增或增强：

- 旧微信账号与轻友主档的一对一约束
- 身份证、护照标识类型
- 期次逐日安排
- 报名订单号、订单应付金额、订单付款状态
- 订单级交易关联
- 逐日签到
- 私人每日记录
- 14/21 日习惯计划
- 私人记录与公开动态的显式关联
- 内容举报
- 微信订阅偏好
- 活动签到与内容举报的两级后台菜单

## 5. 发布前必须完成

1. 在阿里云 RDS 克隆库或临时测试库执行两份业务迁移，不能先在生产库试错。
2. 核对 RDS 为 MySQL 8.0，并确认迁移账号具有 `ALTER/CREATE/INDEX/REFERENCES` 权限。
3. 迁移前创建可恢复备份，记录备份集 ID、时间点和回退方式。
4. 在具备 JDK 8 与 Maven 的构建环境执行 `mvn clean package -DskipTests=false`；当前电脑没有可用的 Java/Maven，不能把合同测试等同于 Java 编译通过。
5. 让新 API 与旧小程序登录服务连接同一个 Redis、同一个 `lifestyle` 数据库。
6. Nginx 将小程序新业务地址转发到 `life-admin-api`；旧 `/servers` 内容接口暂时继续转发到 `lightlife-service`。
7. 用测试微信账号完成：首次身份建档、本人报名、代多人报名、人工确认、订单付款、三日签到、私人记录、举报处理。

## 6. 当前明确边界

- 付款仍为线下，不接微信支付；后台只记录真实收款结果。
- 微信订阅目前只保存用户授权偏好；正式消息发送还需要模板 ID、微信小程序密钥及发送结果日志。
- ASR/LLM API Key 不写入数据库和前端代码；本轮也未启用 AI 自动写入轻友档案。
- 生产 RDS 尚未变更，现网不受本轮本地代码影响。
