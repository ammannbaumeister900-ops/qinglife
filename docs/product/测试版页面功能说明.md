# 轻生活测试版页面功能说明

版本：V1.3.2 功能快照  
整理日期：2026-09-09  
用途：按页面说明当前测试版本“有什么功能、如何使用、为什么做”，供产品讨论、运营培训及验收对照。

## 一、范围与阅读说明

正文以 `deployment/staging/miniapp` 当前小程序测试工程为准，补充与报名闭环相关的测试后台核心页面。功能目标是本次整理对功能用途的说明，不表示对应运营效果已经达成。

- 小程序：四个主频道——首页、轻体营、轻读、我的。
- 后台：轻友档案、期次、报名与付款、签到等核心运营页面；依据当前源码及最近部署验收记录整理。
- 小程序连接隔离测试 API；轻读使用明确标识的演示数据，个人经历和感受不能用虚构数据填充。
- 本文是当前实现说明，不替代产品设计规范，不把早期方案或遗留页面全部算成已上线功能。
- 本轮只整理文档，没有修改代码、发布版本或调整业务数据。

### 状态含义

| 状态 | 含义 |
| --- | --- |
| 已接测试业务 | 页面已调用隔离测试业务接口；不等于每项均已完成手机实机验收。 |
| 已有页面交互 | 页面、导航或展示逻辑已实现，不一定涉及服务端存储。 |
| 演示内容 | 用于展示栏目和阅读效果，不是正式文章或真实轻友投稿。 |
| 本机模拟 | 只在本机保存或模拟结果，不能作为真实业务完成凭证。 |
| 保留待接通 | 页面或入口保留，但当前测试环境未接通对应数据服务。 |

### 核心业务口径

1. **老轻友价格按实际参与人判定**：本人完成过至少一期轻体营。当前服务端以本人已有已确认报名、对应期次已完成为依据，不以购买人或邀请人的经历代替，也不按打卡次数判断。
2. **报名确认与付款分开**：自动确认表示名额确认，不表示已付款；当前付款由后台登记线下收款，不提供微信在线支付。
3. **多人报名逐人计价、逐人留档**：新建期次默认新轻友 3800 元、老轻友 2500 元；运营可以调整本期价格，已有订单保留价格快照。
4. **个人感受仅本人可见**：替家人报名可以涉及其报名安排，但不能因此读取或填写其私人感受。
5. **邀请由用户主动分享**：准备邀请不等于已发送，不自动向微信联系人发消息。
6. **近期动态目前指近期公开活动**：没有独立的品牌新闻、动态编辑与发布模块。

## 二、页面地图

### 小程序主路径

| 主频道 | 二级或流程页面 |
| --- | --- |
| 首页 | 本期详情、本期报名、当前活动安排、体验回顾、轻读 |
| 轻体营 | 活动详情 → 报名两步 → 报名结果 → 本次安排 → 感受记录／体验回顾 → 邀请下一期 |
| 轻读 | 主题筛选／搜索 → 文章详情 |
| 我的 | 全部参与经历、本次参与经历、私人记录、内容收藏、设置与隐私、历史打卡 |

技术上部分页面复用同一个路由，通过 `view` 区分业务界面。本文按用户看到的页面分开描述，不把“共用代码文件”当作“只有一个页面”。

### 完整业务闭环

工作人员创建期次 → 工作人员生成邀请 → 新轻友打开邀请并报名 → 自动确认或人工确认 → 查看活动安排 → 工作人员核验签到、本人记录感受 → 活动结束回顾 → 符合条件的老轻友邀请朋友参加下一期。

## 三、小程序：主流程页面

### M01 首页

入口：底部“首页”。路由：`pages/home/index`。  
页面目标：让初次接触者理解轻生活，让已经参与的轻友知道当前可以做什么。

| 功能 | 功能描述 | 目标 | 当前状态／条件 |
| --- | --- | --- | --- |
| 轻生活介绍 | 展示轻生活关注日常节奏、线下体验、小练习与阅读的定位。 | 在报名前回答“轻生活是什么”，减少只看到课程卡片却不了解品牌的问题。 | 已有页面交互；介绍文案在前端维护。 |
| 初次参与者问题说明 | 从“忙到顾不上自己”“想开始却没头绪”“希望有人同行”介绍参与价值。 | 帮助未报名者判断自己是否有兴趣进一步了解。 | 未登录或当前无报名时展示。 |
| 老轻友欢迎与支持 | 本人有完成经历时，展示欢迎回来、允许慢慢来的支持文案。 | 延续活动后的陪伴感，减少把轻生活理解成一次性课程。 | 已接测试业务；按本人完成经历判断。 |
| 当前任务卡 | 按报名与活动状态提示等待确认、查看准备与行程、查看安排变化或回顾本次体验。 | 减少用户寻找“下一步”的成本。 | 已接测试业务；有报名时显示，行动随状态变化。 |
| 下一期活动摘要 | 展示优先推荐的可报名期次、日期、城市、公开地点及新老价格。 | 把品牌理解自然衔接到具体参与机会。 | 已接测试业务；暂无可报名期次时显示说明。 |
| 报名与查看详情 | 同一卡片提供两个入口，分别进入该期报名流程和详情页。 | 兼顾已经决定参加的人与还需要了解的人。 | 已接测试业务；携带明确期次 ID。 |
| 查看全部期次 | 跳转轻体营频道。 | 让时间不合适的用户继续比较其他期次。 | 已有页面交互。 |
| 轻读支持入口 | 以“先了解，再决定”或日常支持文案引导阅读。 | 为暂不报名及活动结束后的用户提供低压力入口。 | 已有页面交互；当前轻读为演示内容。 |
| 温和刷新与重试 | 再次刷新时保留已加载内容，显示轻量更新提示；失败提供重试。 | 避免反复清空页面带来的闪动，保留阅读上下文。 | 已有页面交互；登录失效时清理相关个人展示。 |

| 下一期优先展示 | 可报名期次优先，再按开始日期排序，第一张卡片强化展示。 | 让近期参与机会出现在第一屏。 | 已有页面交互，基于测试期次数据。 |
| 活动信息比较 | 展示期号、名称、日期、城市与公开地点、新老价格和状态。 | 支持按时间、地点及费用选择。 | 已接测试业务。 |

| 功能 | 功能描述 | 目标 | 当前状态／条件 |
| --- | --- | --- | --- |
| 活动介绍与状态 | 展示名称、简介、当前开放情况。 | 确认打开的是哪一期，以及是否可以参加。 | 已接测试业务。 |
| 时间、地点、人数 | 展示活动日期、天数、公开地点及人数上限。 | 支持判断行程与出行条件。 | 已接测试业务；完整集合地点的受限展示仍需补齐，不能仅凭页面文案认定已实现。 |
| 活动日安排 | 按活动日展示主题、天数与时间。 | 让用户理解每天的大致节奏。 | 已接测试业务；依赖该期已有日程数据，日程为空时无法展示完整安排。 |
| 新老轻友价格 | 展示本期新轻友价格、老轻友价格及逐人计价说明。 | 在报名之前明确费用口径。 | 已接测试业务；最终订单金额由服务端计算。 |

页面目标：让用户在知晓必要条款、参与者及价格规则后提交。

| 功能 | 功能描述 | 目标 | 当前状态／条件 |
| --- | --- | --- | --- |
| 服务必要信息确认 | 用户勾选用于报名、签到与履约的必要信息条款。 | 明确本次服务处理信息的用途。 | 已接测试业务；未同意不能正常提交。 |
| 报名信息复核 | 展示本期期次、日期、公开地点、参与人数及参与者名单。 | 让用户发现错期、漏人或多选。 | 已有页面交互。 |
| 价格与规则复核 | 展示新老价格规则、取消规则和身体边界。 | 减少报名后的理解分歧。 | 已有页面交互；提交前未显示每人的最终资格核价明细及精确合计，订单应付在结果中回读。 |
| 返回修改 | 通过“上一步”修改参与者信息。 | 允许在最终提交前纠正。 | 已有页面交互。 |
