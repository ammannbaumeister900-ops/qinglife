## 0. 一页结论

Web 后台是轻生活业务的完整管理与数据治理中心，不是旧后台菜单的简单换皮。它负责把三端产生的事实汇入同一套业务系统：

```text
轻友端小程序：了解、报名、体验、内容、习惯与本人记录
内部移动 H5：现场查人、快速记录、任务与异常处理
Web 运营后台：配置、批量管理、统一档案、审核、分析和治理
                         ↓
                    同一业务 API
                         ↓
          同一 Customer / Session / 时间线 / 审计事实
```

首期最重要的不是做完所有菜单，而是跑通：

```text
创建 Session → 承接报名 → 现场履约 → 体验/回访
→ 进入统一轻友档案 → 形成下一步运营任务
```

## 1. 产品目标与边界

### 1.1 产品目标

1. 让运营人员在一个后台完成活动、轻友、报名、履约、交易、回访和内容管理。
2. 建立唯一轻友主档，并连续呈现每次 Session 的参与和服务时间线。
3. 让 Web 后台、移动 H5 和轻友小程序只通过同一业务 API 修改同一事实。
4. 对敏感信息、身份合并、状态更正、导出和 AI 处理形成权限与审计闭环。
5. 复用现有后台成熟基础件，减少账号、角色、菜单、日志、字典、导出等重复建设。

### 1.2 当前不做

- 不建设商城、库存、采购或复杂财务系统。
- 不建设全渠道营销自动化和复杂会员等级体系。
- 不做心理、医疗或人格诊断。
- 不用 AI 自动决定权益、服务资格或用户价值。
- 不把旧公开动态直接当成统一档案事实。
- 不把旧数据库继续无限加字段作为新业务主模型。

## 2. 现有后台审计与复用策略

### 2.1 当前技术资产

| 层级 | 当前资产 | 判断 |
|---|---|---|
| 管理前端 | Vue 2、Vue Router、Vuex、Element UI、Axios、ECharts | 可作为现有后台延续开发的基础，但需逐步升级依赖 |
| 管理后端 | RuoYi 衍生 Spring Boot 多模块系统 | 可复用认证、RBAC、菜单、日志、字典、任务、监控等基础能力 |
| 现有业务页面 | 用户、文章、标签、收藏、公开动态、评论、点赞、发布模板、联系方式 | 作为内容和历史社区迁移来源，不等于新运营系统 |
| 数据导出 | Excel 导出和通用列表能力 | 可复用实现思路，新增敏感字段权限和导出审批/审计 |
| 文件能力 | OSS/上传基础件 | 安全加固和配置收口后选择性复用 |

### 2.2 允许复用

- 后台账号、角色、菜单和按钮权限框架。
- 操作日志、登录日志、字典、定时任务和系统监控思路。
- 通用列表、分页、筛选、导出和表单组件。
- 文章、标签、联系方式等可验证的历史业务数据。
- 旧微信用户作为历史身份映射线索。

### 2.3 不直接继承

- “盲盒后台”等模板品牌、菜单和包信息。
- 旧用户表作为统一轻友主档。
- 旧动态发布模板作为体验、复食或习惯任务模型。
- 旧小程序 API 作为新业务写入主干。
- 代码和配置文件中的历史密钥、密码、证书及环境地址。

### 2.4 上线前技术前置条件

1. 轮换源码和历史交付物中出现过的全部密钥与密码。
2. 测试、预发布、生产环境配置分离，密钥不进入仓库。
3. 修复依赖高危漏洞，再确定 Vue 2 原地维护还是分阶段升级。
4. 新业务接口放在独立业务域，不继续复制表生成式控制器。
5. 对下载、上传、文档、监控等匿名访问路径重新做生产安全审计。
6. 旧库先只读迁移，完成映射报告和回退演练后再切换写入口。

## 3. 用户、角色与权限

| 角色 | 主要职责 | 关键权限 |
|---|---|---|
| 运营人员 | 日常报名、名单、轻友和回访 | 查看必要业务信息、录入和更正授权范围内事实 |
| 活动负责人 | 负责特定 Session 的履约 | 场次、名单、参与状态、场后事实与异常 |
| 内容运营 | 维护文章、通告、视频和目录 | 内容编辑、提交审核，不默认查看轻友敏感档案 |
| 内容审核人 | 健康/品牌内容审核 | 审核、驳回、下架、版本回退 |
| 财务/交易人员 | 核对交易事实 | 查看和更正 Transaction，不查看无关健康信息 |
| 数据管理员 | 导入、查重、合并和质量治理 | 身份冲突、合并、导出和数据质量处理 |
| 超级管理员 | 系统和权限配置 | 账号、角色、敏感字段、审计、系统配置 |

权限至少控制到：

- 页面与菜单。
- 操作按钮。
- 数据范围：全部/城市/负责 Session/本人任务。
- 敏感字段：脱敏/明文/不可见。
- 导出字段与导出范围。
- AI 能力使用和结果确认。

## 5. 页面开发需求

### W01 登录与工作身份

- 使用内部员工账号登录，不允许多人共享账号。
- 首期支持账号密码；正式上线建议对高权限角色增加 MFA。
- 登录后展示当前角色、数据范围和最近登录信息。
- 账号停用、角色撤销后服务端立即失效。

### W02 运营总览

#### 页面目标

回答三个问题：今天发生什么、哪里需要处理、整体闭环是否健康。

#### P0 模块

- 今日待办：报名待确认、现场异常、回访到期、交易异常、AI 待确认。
- 近期 Session：日期、城市、带领人、容量、报名、确认、到场状态。
- 核心漏斗：报名启动、报名提交、确认、到场、完成、复盘、第3天回访。
- 数据质量：疑似重复、缺失手机号、未关联 Session、无来源记录。

每个指标必须同时展示时间范围、分子、分母和口径说明。

### W03 轻友列表

#### 搜索与筛选

- 姓名、小名、手机号后四位、轻友 ID。
- 最近/首次 Session、城市、来源、当前服务阶段。
- 是否有待办、剩余卡次、最近联系时间、授权状态。

#### 列表字段

轻友、脱敏手机号、最近 Session、当前阶段、最近联系、待办、负责人、数据质量状态。

#### 快捷操作

查看档案、记一条、建回访、录交易、处理身份冲突。

### W04 轻友统一档案

页面顶部始终展示：轻友 ID、姓名/称呼、脱敏手机号、当前服务阶段、最近 Session、负责人、待办状态。

```text
概览
参与时间线
沟通与回访
交易与卡次
体验与计划
内容与公开记录
身份/关系
授权与审计
```

关键规则：

- 用户事实、本人自述、他人代填、工作人员观察、工作人员判断和 AI 草稿分区展示。
- Session 经历是时间线主轴，不把多期经历压成一个静态标签。
- 首次推荐关系不被后续活动来源覆盖；单次归因挂在对应 Session。
- 合并档案必须显示依据、冲突字段、保留值和回退记录。
- 敏感字段默认脱敏；查看明文和导出进入审计。

### W05 产品、模板与 Session

- Product：名称、定位、适用边界、展示费用、状态。
- ActivityTemplateVersion：详情、流程、问题、固定节点、规则版本。
- Session：唯一期号、产品、模板版本、日期、地点、容量、负责人、报名截止、状态。
- 已发生的 Session 和已发布模板不得被新编辑覆盖历史。
- 取消、延期、换场地必须形成状态历史和通知任务。

### W06 报名管理

- 按实际参与者统计，报名批次只表示一次多人报名动作。
- 展示报名发起人、主要联系人、实际参与者、成年手机号/未成年人标记、Session、来源、推荐人和状态。
- 支持确认、候补转正、取消、改期、异常修正和导出。
- 报名状态与交易状态分离。
- 关键状态修改要求填写原因并记录旧值、新值、操作人和时间。

### W07 现场名单与参与状态

- 按 Session 展示名单和同行组，逐人处理核验、签到、迟到、缺席、中途退出和完成。
- 成年手机号缺失必须进入异常队列；未成年人不以手机号缺失判错。
- 误签和身份修正可回退，不能直接覆盖原记录。
- 带领人主要通过小程序授权入口操作；运营后台保留补录与异常处理。

### W08 快速记录与 AI 待确认

支持文字、语音转写、图片/截图、交易和任务五类入口。

```text
原始输入 → 识别轻友/Session → ASR → LLM 结构化草稿
→ 人工确认 → 正式时间线/待办
```

- ASR/LLM 失败不影响原始记录保存。
- AI 只生成草稿，不自动修改主档、合并身份或形成敏感标签。
- 保存模型、规则/提示词版本、输入范围、输出、耗时、费用和确认人。
- API Key 只存服务端密钥配置，不进入浏览器、日志或数据库明文字段。

### W09 回访与任务

- 第3天任务按 Session 完成时间生成。
- 人工任务包含轻友、Session、任务类型、负责人、截止时间、优先级和结果。
- 支持待处理、处理中、已完成、跳过、失败、关闭。
- 完成任务时必须留下结果；需要继续服务时可生成下一条任务。

### W10 交易与卡次

- Transaction 独立于报名和订单概念。
- 支持线上回调、固定二维码、现金、转账及其他真实方式。
- 关联 Customer、Session、金额、发生时间、方式、外部流水号、状态和来源。
- 无外部流水号时只提示疑似重复，人工确认。
- 更正、退款、取消和导出进入审计。

### W11 陪伴计划

- 管理复食、14/21 日计划模板和每日任务版本。
- 任务定义与用户响应分离，修改模板不覆盖历史记录。
- 状态支持完成、轻量、休息、暂停和继续，不制造失败评价。
- 健康相关内容发布前必须有审核人、版本、风险提示和下架机制。

### W12 内容中心

- 统一管理文章、通告、图片、视频和目录内容。
- 身体困扰、区域、穴位与练习是内容导航，不是诊断模型。
- 支持草稿、待审核、已发布、已下架和版本回退。
- 视频管理封面、时长、字幕、授权、风险提示和存储状态。
- 内容修改后生成新版本，不覆盖历史任务引用。

### W13 轻友公开内容治理

- 管理公开动态、评论、举报、审核、删除和申诉。
- 私人记录与公开副本分离；审核人员不默认访问无关私人原记录。
- 自动敏感词只提示风险，不替代人工复核。
- 品牌二次使用轻友动态需要独立授权。

### W14 Excel 导入、查重与合并

- 支持工作表选择、字段映射、预览、格式校验和逐行错误报告。
- 历史一行先作为参与记录候选，再关联 Customer 和 Session。
- 手机号强匹配、姓名/生日等仅作为候选证据；同名不自动合并。
- 保存文件、工作表、行号、批次、导入人、导入时间和原始值。

### W15 权限、审计与数据请求

- 查看敏感详情、修改、导出、合并、删除、授权变更和角色分配均审计。
- 支持轻友更正、撤回授权、删除和注销申请的内部处理流。
- 测试环境不得直接使用未脱敏真实用户数据。
- 高风险操作显示影响范围并要求二次确认。

## 6. 核心状态

| 对象 | 状态 |
|---|---|
| Session | 草稿、开放报名、报名截止、进行中、已结束、已取消 |
| Registration | 草稿、待确认、已确认、候补、已取消、已改期 |
| IdentityVerification | 未核验、已核验、待修正、已修正 |
| Participation | 未到场、已签到、迟到、缺席、中途退出、已完成 |
| FollowUpTask | 待触发、待处理、处理中、已完成、跳过、失败、关闭 |
| AIProcessingRun | 待处理、处理中、待人工确认、已确认、失败、已放弃 |
| ContentItem | 草稿、待审核、已发布、已驳回、已下架 |
| HabitPlan | 待开始、进行中、已暂停、已完成、已结束 |
| Transaction | 待确认、成功、失败、退款中、已退款、已取消 |

所有状态变化必须通过明确动作发生并保留历史，不允许直接覆盖关键状态。

## 8. API 边界

三端共用业务服务，不共用无限权限。建议按业务域组织：

```text
/api/auth/*
/api/customers/*
/api/sessions/*
/api/registrations/*
/api/participations/*
/api/interactions/*
/api/follow-ups/*
/api/transactions/*
/api/plans/*
/api/content/*
/api/community/*
/api/imports/*
/api/audit/*
/api/ai/*
```

约束：

- 小程序、移动 H5 和 Web 后台使用不同客户端权限和响应字段。
- 服务端按账号、角色、Session、数据范围和字段再次鉴权。
- 写接口支持幂等键，避免重复签到、重复交易和重复记录。
- API 不返回与当前任务无关的敏感字段。
- 列表接口默认分页，导出走独立任务和审计链路。

## 10. 正式开发建议

### 阶段 0：安全与迁移准备

配置收口、密钥轮换、依赖审计、旧库只读快照、迁移映射和回退方案。

### 阶段 1：统一业务底座

Customer、Session、报名、参与、交易、授权、时间线、权限和审计。

### 阶段 2：运营闭环

总览、轻友档案、现场履约、快速记录、回访任务、导入和数据质量。

### 阶段 3：V1.2 内容与陪伴

阶段化首页、内容中心、复食/习惯模板和轻友内容治理。

### 阶段 4：AI 辅助

ASR、结构化草稿、证据化查询和运营建议；始终保留人工确认与失败降级。

## 11. 验收标准

### 11.1 业务

- 可从 Session 进入报名、参与、体验、回访和交易事实。
- 可从轻友进入跨 Session 时间线，不把多人代报名人当成数据主体。
- 首次推荐和本次归因同时存在且不互相覆盖。
- Web 与移动 H5 修改后读取到同一状态。

### 11.2 权限与审计

- 无权限人员无法通过直接接口获取敏感字段。
- 查看明文、修改、导出、合并和 AI 确认均可追溯。
- 角色撤销后权限立即失效。

### 11.3 可用性

- 常用任务从首页两次操作内进入。
- 轻友可通过姓名、小名、手机号后四位或 ID 找到。
- 快速记录不要求先填写大量结构化字段。
- 空状态、错误状态、加载状态和无权限状态均有明确反馈。

### 11.4 非功能

- 正式环境不包含仓库明文密钥。
- 生产和测试数据隔离。
- 数据库迁移、备份和恢复通过演练。
- 核心状态写入具备幂等和并发保护。
