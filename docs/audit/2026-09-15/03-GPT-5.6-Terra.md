## T-01｜修复 Failsafe 集成测试类路径

**P0；失败已复现；问题置信度高，根因判断中。**

### 问题与原因

当前 MySQL 集成报告为 **7 项、6 通过、1 失败**。`productionGuardAcceptsTheMigratedIdentityConstraints` 报 `NoClassDefFoundError: com/yicai/web/config/ProductionSchemaGuard`。Failsafe 未显式配置 classesDirectory，优先检查是否错误使用 Spring Boot 重打包 jar 作为普通测试类路径。这不证明生产运行一定缺少该类。

证据：`server/api/box-web/pom.xml`；`server/api/box-web/src/test/java/com/yicai/web/integration/LoginConcurrencyIT.java`；`server/api/box-web/target/failsafe-reports/com.yicai.web.integration.LoginConcurrencyIT.txt`；`.tools/mysql-integration-final.log`。

### 修复步骤

1. 查看 effective POM、实际产物和测试类路径，确认重打包影响。
2. 给 Failsafe 指定 `<classesDirectory>${project.build.outputDirectory}</classesDirectory>`，保持生产打包方式。
3. 使用已有隔离 MySQL 参数运行启用 mysql-it 的 `verify`，不能连接生产库。
4. 若仍失败，记录下一条真实异常，不猜测修改业务代码。

### 验收与模型边界

现有 7 项全部通过且无 skip。新增“缺失迁移拒绝启动”负例归 S-01，尚未添加时不能算第 8 项。不得移除 guard 或失败测试。修法局部、结果明确，Terra 足够。

## T-02｜统一工作人员图片下载源站

**P1；源码已确认的配置组合风险，运行复现待补；置信度高。**

### 问题与原因

`apps/miniapp/services/staff-api.js` 用 runtime.businessBaseUrl 拼图片地址，而 token 由 business.login 获取；后者可使用另一有效源站。不同配置来源可能导致请求地址与 token 不匹配。

### 修复步骤

1. 等 S-03 确定环境策略后，复用统一源站解析或授权下载函数。
2. 地址与 token 对应同一允许的源站，按统一规则处理 401、缓存与失败提示。
3. 不在本项自行设计白名单或重写认证。

### 验收与模型边界

用 wx.downloadFile 替身覆盖开发地址覆盖、staging、production，断言 URL/header 一致；不下载真实客户图片。契约确定后是机械适配，Terra 完成；新授权规则交 S-02/S-03。
