## 2. 发现并修复的问题

### 远端提交无法编译

`QlStaffWorkspaceController` 和 `LoginConcurrencyIT` 已引用 contacts、addContact、followUps、addFollowUp、transitionFollowUp，但 `4082f19` 的 `QlStaffWorkspaceService` 没有这些方法。不能依据旧执行报告认定该提交可构建。

本轮补全服务：校验客户、操作权限、负责人、字段和到期时间；沟通与跟进在同一事务提交；结束任务需要结果，结束后禁止重新转换。除原有最小表测试外，新增完整迁移表结构的约束与回滚测试。

### A-01：报名、名额、付款及取消

- `QlRegistrationPolicy` 统一 pending/confirmed 占用名额，waitlisted 不占用。后台、小程序、工作人员均走共享规则。
- 新增要求期次 open、处于报名窗口、未超过结束日期；待确认转确认不额外占一个名额，候补转占位须重新检查容量。
- 锁顺序为期次优先，再订单/报名，再出勤；取消、付款与到场更新遵循共同入口，避免付款与取消得到矛盾结果。
- 后台与工作人员使用同一个足额付款规则和付款方式列表；零价期次允许 0 元，不放开少付款。
- 已付款或已有实际到场记录，不能直接取消/降级。已取消记录不能直接恢复；本期继续不开放改期。
- 多人订单禁止从单人编辑入口局部取消；新增后台“取消整单”，要求整单未付款且所有参与人满足取消条件，全部写入和日志共同提交，重复请求不重复记取消日志。
- 保留既有价格和付款快照，不追改旧结算金额。
- 真正的时间映射缺陷已由测试复现：JDBC 将 DATETIME 返回为 LocalDateTime 时，旧 Date 类型判断会跳过截止检查。现统一转换为 Asia/Shanghai 对应时间再比较。

### 统一审查追加修复

- 安全匹配：受保护的 doc.html/文档路径必须先于匿名静态后缀规则；private profile 也先匹配鉴权规则。
- 下载：规范化后再检查真实路径，防止符号链接/目录联接越出允许根目录。后台下载改为携带 Authorization 的请求，移除 GET delete 参数，并拒绝把 JSON 错误下载成文件。
- 生产请求/上传上限使用 DataSize 解析并要求正值，覆盖 -1MB、0B 等原字符串比较漏掉的配置。
- 老学员/邀请/参与判断：有每日出勤事实时优先采用每日记录；旧汇总只在没有每日记录时回退，并按客户与期次匹配，兼容没有 registration_id 的历史事实。
