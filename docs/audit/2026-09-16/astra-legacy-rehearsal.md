## 对象与隔离

源为轻生活测试服务器上的 qinglife_test（MySQL 8.0.46），不是生产库。先确认全部业务表为 InnoDB，触发器、事件、存储过程数量均为零，再执行 single-transaction 一致性导出。源库未执行 DDL/DML，未停写或重启已有服务。

备份保留在服务器专用 audit 目录，目录/文件通过 umask 077 限制权限；未下载数据库内容到本机或上传 GitHub。恢复到两个新建的独立演练库，资源名称与备份路径保存在本机忽略目录 .tools/legacy-rehearsal-current.json，后续验收完成后统一处理。

## 实际结果

1. 同一备份分别恢复两次，79 张表的 CHECKSUM TABLE EXTENDED 值全部一致。
2. 在升级副本运行 server/operations/preflight-v1.3.10.sql，10 项问题计数均为零：重复 OpenID、尾空格、过长 OpenID、重复旧账号绑定、孤立绑定、报名/整单期次不一致、付款状态不一致、负卡余额、超额名额、缺失价格快照。
3. 原库迁移登记最高 1.3.10，部分历史文件未登记校验和；既有 legacy_app_user_id 唯一索引已经存在，OpenID 唯一索引缺失。没有通过补写迁移日志伪装成完整执行过全部新迁移。
4. 只在升级副本执行现有 V1_3_11__wechat_login_identity.sql，成功建立完整 OpenID 唯一索引并变更为 utf8mb4_bin。
5. 升级后的79张表数据校验值与升级前全部一致。
6. 升级副本与本机空库完成14文件迁移的基线比较：811项字段元数据完全一致（列名、类型、可空性、排序规则），248项索引条目完全一致（名称、唯一性、列顺序、前缀长度、索引类型）；比较排除了新工具专属 ql_migration_run 日志表。

以上均为执行证据，不是仅凭 SQL 文件推断。
