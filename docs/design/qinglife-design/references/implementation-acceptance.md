# 实现与验收

进入小程序实现、批量优化或冻结样板修订时使用。内容承接 V1 的工程判断，规则不变，只从设计方法中分离出来。工程、Git、安全与工作树规则仍以两级 `AGENTS.md` 为准；用户当前授权决定执行范围，本文件不授权批量修改、业务变更或发布。

## 1. 已验样板的决策模式

先读当前完整 WXML / WXSS / JS、数据映射与公共组件，再决定最小调整。这些是判断模式，不是组件模板。

| 模式 / 已验样板 | 应保留的主次 | 避免的错误 |
| --- | --- | --- |
| 品牌发现 / 首页 | 无待办时真实人物和主故事形成焦点；有待办时当前任务先行 | 把品牌开篇复制到服务页；把内部视觉样稿写进接口 |
| 活动决策 / detail | 活动身份与事实 → 体验感受 → 条件、带领者、费用、安排、规则 → 原报名动作 | 冗余散文标题、重复规则、海报裁切；凭测试日程数推断课程天数 |
| 活动比较 / 公开列表 | 期次与名称、时间地点、实际状态、两档公开价及费用说明；沿原排序突出首条 | 擅改推荐与排序；把详情全搬来；自动滚动心声。心声默认短预览、手动切换，无则隐藏 |
| 任务与状态 / 我的安排 | 期次与报名状态 → 名称独行 → 日期城市 → 必要状态与操作；多期有当前/历史时才分组 | 操作挤标题；历史分组藏待办；从结束日期推断完成或付款 |
| 填写与核对 / register | 当前步骤 → 对象与字段分组 → 必要条件与费用 → 真实提交核对 → 主动作 | 摄影开篇；每字段一张卡；只用 Toast；自行算出接口未确认的应付总额 |
| 公共阅读 / 文章 | 自然标题、真实作者与日期、关联封面、完整正文、出处与克制的收藏/分享 | 固定人物身份、引语、断行或段落；统一添加无关健康提示；把长正文当冗余文案 |
| 私人阅读与表达 / experience | 已有原文先读；活动归属、阶段、时间、可见性辅助；新增/编辑按真实资格出现 | 新增表单压过记录；无评分反复「未填」；混淆私人记录与可授权心声 |

封面策略按角色：公开活动列表沿用动态期数模板；我的安排用无封面任务目录；私人回顾无摄影。这些是已确认样板的具体选择，不推广为全站规则。

## 2. 表单、设置与结果页

- 步骤写任务名称，当前步与下一步清楚；换步起点可见，返回保留已有输入。
- 字段按信息归属分组；标签注明必填/选填、单位和必要选择规则，不只依赖占位符。单选、多选及互斥「无」可理解，不改原校验条件。
- 错误就近定位到实际字段或参与者，原位可修复并保留输入；Toast 只作辅助。
- 核对页显示真正将提交的对象和既有兜底值，不虚构确认项。区分未授权、提交中、失败、成功，保留防重复提交与既有请求语义。
- 设置区分本机偏好与真实服务能力：保存偏好不等于通知已开通。

## 3. 私人内容

- 用户原文、换行和已有顺序优先；长文可主动展开，全文可达。
- 归属与可见性清楚而克制；私人内容不随邀请、代报名或公开心声泄露。
- 视觉任务中不新增私人文字持久化、跨身份草稿或新的阶段入口。失败保留草稿；异步保存只确认已提交快照，不吞掉在途修改。
- 可选评分没有值时不伪造数字；编辑文字不丢已有评分。

## 4. 富文本与长期运营

- 后台负责内容结构，前台负责统一阅读样式。先核编辑器 → 存储 → API → 原生渲染链路；共用能力不等于共用页面构图。
- 保留标题层级、段落、强调、列表、引用、图片顺序与安全链接语义；字号与任意颜色按阅读规范归一，不透传任意 HTML/CSS。图片不溢出、不变形。
- 沿用受控节点与标签/属性/URL 安全处理；前端过滤不代表服务端安全。
- 以编辑器实际能力验收：视频、表格、外链可保存不等于可播放、可排版、可打开。

## 5. 真实数据与自然退化

- **无内容**：区分读取中、失败、真的为空与无权限。失败可重试，空态只给真实可用的下一步。可选模块无内容时自然消失；必要但未知的事实标「待核对」，不伪装为 0、已确认或已完成。
- **缺字段**：不留空标题、空分隔符或占位署名。价格 0 与价格缺失、评分缺失与零分要区分。不承诺未实现的提醒、短信、草稿恢复或回读。
- **长内容与窄屏**：名称有独立宽度，状态和操作可换行；日期、价格、条件仍可读。不以缩小所有文字解决溢出。
- **多期、多条、多阶段**：保持原关联、筛选、排序、权限及精确跳转 ID；历史未处理事项不因归档视觉而消失。课程天数按实际起止日期，与日程条数分开。
- **测试素材**：真实内容不足时，用隔离的内存夹具或非生产测试内容并标明来源；不写入正式接口补版面。未取得的真实数据、保存或真机证据列为未验。

## 6. 自主决策与暂停

- 已授权范围内，普通视觉、界面文案减法、排版和保留语义的轻度交互优化自主完成，不逐项审批。页面包含隐私字段、费用或登录，不等于普通排版也要重新审批。
- 需要改变业务流程、权限/隐私、数据含义或持久化、接口契约，或出现现有规则无法判断的重大设计冲突时，暂停受影响部分，提交：现有事实、冲突、单一建议、影响范围。其余已授权工作继续。
- 不擅改角色比例；调整建议与当前执行分开。原有技术缺口不默认列为本批必修。

## 7. 逐视图验收闭环

每批可含多个已明确视图，逐视图完成小闭环。共用文件按分支限定样式；涉及共享组件时核对真实调用者，避免带改冻结页面。

1. **记录基线**：按 AGENTS 核对工作树；记录入口与角色、主要任务、现有字段/状态/权限、原跳转和本轮允许改动；保存修改前实际截图，取不到时记录缺口。
2. **决定增删**：明确保留/调整/删除与一句理由，先层级后样式。
3. **实施验证**：先受影响功能，再相关静态检查/测试与相邻分支回归。不为纯样式写镜像断言，不无条件跑全库。已有失败先复现对照。
4. **关键状态**：按真实支持能力覆盖正常、加载、错误/重试、空/缺字段，以及相关的登录/无权限、禁用、提交中/失败/成功；列表查 0/1/多项与筛选；表单查返回、错误定位、输入保留。
5. **实际布局与交互**：在微信开发者工具检查正常宽度与代表性窄屏、长文与长标题、图片失败、展开收起、固定返回/操作/Tab/安全区。保存主要状态截图与前后差异；夹具与真实接口证据分别标明。
6. **收尾复核**：检查仍可删除的解释性文字、容器和重复入口；确认关键事实、完整内容、权限与跳转保留；核对 diff 与允许范围；交付改动、验证、历史失败与新增问题、截图、未验证项与真机路径。

无法运行开发者工具或缺验收身份时，完成可验证部分并明确标记未验。真机、真实保存、生产发布与开发者工具分别记录；上传微信或外部服务、发布遵循单独授权。

原生适配：沿用导航、返回、胶囊测量、Tab 与安全区；长页滚动后仍能返回；不复制 HTML 模拟微信状态栏，不用未经验证的浏览器 CSS 撑起原生布局。
