# 自主优化分批方案与规则演练

2026-10-10，依据当前工作树及已确认角色矩阵。**这是待统一授权的执行建议，不代表已开始改页。** 不调整比例，已确认七类样板保持冻结与统一真机队列。批次按旅程、复用规则与修改风险分组；每个视图完成状态/截图/回归后再推进下一个。不是要求逐页重新人工设计。

## 分批范围

| 批次 | 具体视图 | 重点与验收边界 |
| --- | --- | --- |
| 1 · 首批 | `camp-flow/journey`；轻友登记填写 `friend-registration` 的 form 分支 | 补齐报名后的服务理解与参加前采集。状态/下一步、四步任务、字段规则/错误；保留原接口、授权、校验、草稿和落点。共用文件中冻结的 detail/register/experience 不带改 |
| 2 · 核对与公开表达 | 轻友登记 history/detail/保存结果；`camp-reflection` | 日期/期次/修改期限、答案核对、保存下一步；公开心声按原公开范围/审核/授权呈现。敏感信息用途及早期记录快照说明不能按冗余删掉 |
| 3 · 内容发现与阅读 | `content` 故事浏览、默认/主题、搜索；article 方法文章 | 同一内容不同发现/检索角色；真实封面可用才用，缺图仍成立；正文/出处与已有健康提示。保留故事样板，通用文章容器缺口独立评估，不借此整修公共渲染器 |
| 4 · 个人服务与检索 | mine；`personal/experiences`；`mine-flow/collections`、privacy | 目录、逐期状态、收藏重读、本机设置与服务能力分离；保留卡次/收款事实和已有跳转，不擅改菜单业务排序 |
| 5 · 私人内容与日常任务 | `personal/records`；`camp-flow/feeling`；`friend-flow/daily`；`mine-flow/habit` | 原文先读、写作规则明确、当前计划状态；删系统引导和装饰，不删真实原文或隐私范围，不新增记录入口/存储能力 |
| 6 · 邀请与归档 | referrals 制作邀请/推荐记录；`camp-flow/invite`；`friend-flow/archive` | 减少制作负担、持续显示实际目标、记录易核对、归档原文优先。只优化现有入口的层级与定位，不发明分享或直达业务路径 |
| 7 · 工作人员与兼容视图核查 | 先 `staff/workspace/desk`；success/auth 及未单列角色的旧入口另审 | 工作台先完成用户端再做，保持数据权限/收款流程。success 先证实可达；auth 先明确演示能力。未定角色、认证/短信及其他 staff 视图不默认进入视觉实施范围 |

首批只建议两个明确视图，均为既定 10/90。顺序 journey → 登记填写；先让现有服务状态可理解，再优化登记效率。首批不改登记历史/详情/保存结果、不改公开列表、不改共享导航或富文本能力。当前共用文件已有未提交改动，必须按现有分支增量处理并回归相邻冻结视图。

## 首批如何落地

- **journey**：活动身份紧凑呈现；报名状态、结算/费用状态分开；突出真实可做的下一步，取消并列等重的状态容器。名称与日期不被操作挤压。不得把“待确认”改成“已安排”、把确认金额当收款，或编造行程内容。沿用原服务落点与资格判断。
- **登记填写**：保留四步、全部字段与条件；强化当前步骤与任务名称，按信息归属分组。精简重复开场，把必要规则放在相应字段/步骤；错误原位可修复，返回/失败不丢输入。敏感信息授权、互斥规则与修改期限保留，不重写业务条款。
- **完成证据**：正常及窄屏实际开发者工具截图、关键报名/费用分支、四步与条件字段/错误/返回/提交反馈、有关身份与权限分支、相关测试及相邻冻结分支回归。只在已授权隔离条件下测试真实写入，缺身份/后端/真机时单列未验。

## 用当前页面演练规则

以下是**只读设计判断**，没有修改页面、运行新的业务测试或新增视觉验收；用于检验同一 Skill 能否得出不同且合适的处理。

| 当前页面证据 | 规则给出的决定 | 保留项 / 不能声称 |
| --- | --- | --- |
| 首页已确认有待办时隐藏品牌开篇，任务期次独立于推荐期次 | 仍先当前任务；不为统一品牌把大图补回待办态 | 原 task ID、动作与推荐分离，不能用比例算图片面积 |
| 公开列表期数模板、两档价、默认公开心声与手动切换已落地 | 延用比较结构；无心声自然隐藏；短预览辅助活动比较 | 原公开心声原文/期次与审核，费用口径，不新增照片或自动轮播 |
| 我的安排已用名称独行、报名/费用分离，历史待办可见 | 任务目录成立，无需添加封面或强行分组单期 | 接口顺序、历史费用待办与原 journey 落点 |
| register 两步；登记填写四步，字段旁已有单/多选和错误 | 复用步骤可理解/就近错误原则，不把登记改成两步 | 授权、必填、互斥“无”、返回输入、原提交校验；不能宣称真实提交已再验 |
| 文章现有标题/元信息、受控富文本、封面去重、方法健康提示 | 故事自然换行，方法正文优先；空态“未找到…”下重复“当前没有…”可删 | 正文结构/图片/出处、必要能力提示、安全白名单；服务端清洗未补齐 |
| experience 现有原文前置、评分可选、活动后编辑与页内草稿 | 不新增摄影/情绪标题；空评分不制造占位；完整原文可达 | 本人范围、原评分和草稿实际恢复范围，before/during 不新增编辑能力 |
| mine“内容收藏”下“把喜欢的阅读留在这里”；“复制微信号”后“在微信中搜索添加好友” | 前者不增加信息，可删；后者交代复制后的必要下一步，按实际任务保留 | 私人记录入口可见性不因文案减法丢失；缺微信号时不伪装可复制 |
| personal records 中原文缺失时补情绪句，空态提示代报名看不到对方记录 | 去掉伪原文，占位不冒充用户感受；归属/阶段继续可识别 | 代报名隐私事实保留；字段缺失不虚构正文或评分 |
| journey 现有报名/费用等状态，success 为兼容分支，auth 有演示短信边界 | 状态分类排版可自主；改变状态结论/落点/真实认证则暂停受影响部分 | 不把未知状态变成确认，不将旧模板作为正式能力；只读演练不是流程改造 |

## 规则冲突与约束检查

- AGENTS 负责工程/Git/安全规则，Skill 增加的是设计判断与设计验收，不再重复审批清单；当前用户授权优先。
- 高品牌允许表达，高功能优先效率；“克制”不再解释为所有页面一律更淡、更小。没有新增统一字号、固定封面比例或视觉面积配额。
- 容器按语义判断，不禁用所有 Card；分隔线不是所有页面必备。文案减法不处理真实正文，也不删除价格/权限/必要规则。
- 现有样板用于验证边界，不成为统一模板；普通批次不强制原型、不逐项审批。重大冲突只暂停受影响部分。
- 保留旧 Skill 的重要事实可读、静态真实内容、原生导航、安全区、真实能力反馈、继承样式复核和停止审美迭代原则；旧绝对化“没有 Card 更好”改为按语义选择。
