# 设计质量检查标准

用于三个时机：出方案后的自审、交付前的复核、评审他人的设计稿。检查的是设计判断，不替代 [implementation-acceptance](implementation-acceptance.md) 的工程验收。

## 判定方式

- **阻断**：任一项不通过，方案不进入用户评审。
- **六个维度**各打 0 / 1 / 2 分：0 = 明显问题，1 = 成立但平，2 = 有判断、有记忆点。总分只用于比较方案，不用于放行；放行看阻断项。
- 每个问题都给证据（截图位置或元素），并说明对用户的影响。

## 阻断项

1. 可读性低于下限：叙事正文 <16px、功能正文 <15px、关键事实 <14px，正文对比度 <7:1、辅助文字 <4.5:1，可点区域 <44px。
2. 素材不实：虚构或 AI 人物冒充轻友、创办人；照片邻接与其身份不符的叙述；未授权素材被当作已授权。
3. 健康与透明：出现疗效、排毒、停药类表达；真实活动安排、适用条件或风险在决定位置不易发现。
4. 跨页撞图：首屏图或故事高点图在相邻页面重复出现。
5. 改动了已确认的业务决定（模块顺序、权限、已定标题与口径、真实跳转）。

## 六个维度

**1 品牌**
- 遮名测试：遮住 Logo 和品牌名，还认得出是轻生活吗？靠的是真实素材、词汇和构图，还是只有配色？
- 真实素材或具体事实是不是主角？
- 语气是否平视、具体，没有养生广告腔或说教？

**2 审美**
- 眯眼测试：眯眼看每一屏，是否有且只有一个焦点？层级能否一眼看出？
- 尺度对比是否存在（大与小、疏与密），还是所有元素差不多大？
- 留白有节奏，而不是处处均匀？
- 去一件饰品：删掉一个装饰元素，页面是否更好？是就删。

**3 可读性**
- 375px 一臂距离：关键事实不凑近也能读清吗？
- 320px、长标题、系统字体放大、衬线回退为黑体时，是否仍成立？
- 字号角色是否 ≤6 个？

**4 叙事**（叙事与决策页）
- 标题连读：只读各段标题，是否连成一条有推进的线索？
- 节奏谱：是否只有一个高点？是否有连续两段使用同一种构图语法？
- 增量测试：逐段问「这一段给了用户什么新东西」；答不出的段落删除或合并。
- 结尾是否落到真实可做的下一步，且透明信息就在旁边？

**5 交互**
- 主动作是否清楚，次动作是否克制但可发现？
- 选中、加载、空、失败、提交中等状态是否可辨，且不只靠颜色？
- 原位切换是否有明确反馈？自动轮换能否暂停与手动操作？
- 固定栏是否遮挡末项或安全区？

**6 跨页面一致**
- 素材账本：同一张图是否在旅程中承担了两次同样的职责？
- 语言账本：核心语是否在多页、多段重复主讲？
- 亲缘而不克隆：字体角色、色彩语义、动作层级一致，构图是否随页面角色不同？
- 信息递进：后一页是否给出前一页没有的证据？

## 自动检查（HTML 原型）

本 Skill 的 `tools/readability-audit.js` 可在浏览器中对 375px 原型运行，输出：最小字号、低于下限的文本节点、对比度不足的文字、可点区域过小的元素、字号种类数。它只覆盖可量化的部分；品牌、审美与叙事仍需人工判断。小程序实现阶段以原生截图与开发者工具检查为准。

## 审稿输出格式

1. **设计读取**：一句话说明页面类型、来的人、表达重心。
2. **结论**：能否进入用户评审；阻断项列表。
3. **六维评分**与每维一句理由。
4. **问题**：按影响排序，最多列 8 个；每个附证据与影响。
5. **修正**：最重要的 3–5 项，写清要变成什么样，而不只是「优化」。
6. **未验证**：截图之外没有证据的内容（真机、真实数据、授权、跳转）。
