# 轻生活设计 · V2

本 Skill 回答「轻生活的设计应当怎样判断」。工程、Git、安全与工作树规则见两级 `AGENTS.md`；业务事实、数据口径、人物与授权见项目 Context 文档；某一页的模块顺序、已定文案和本轮取舍写在该页 Brief。用户当前指令与授权范围优先；冲突时：用户当前指令 > 业务事实与已确认产品决定 > 本 Skill > 历史设计建议。面向原生小程序 WXML/WXSS；HTML 原型只用于评审。

使用前分清三层：

1. **品牌内核**：§1–§2 中标「守」的条目。少而硬，违背即退回。
2. **设计方法**：§3–§5、§8–§9。默认这样想；可以偏离，但要说出理由。
3. **自由区**：§6。Skill 不给答案，期望设计者拿出有观点的方案。

## 1. 品牌内核

**轻生活提供一种重新认识身体和生活的方式。** 设计要让人感到：这里有真实的人，有人带领，可以慢下来，也值得信任。

- **「轻」是减负，不是变淡。** 减掉的是用户的负担——理解成本、操作步骤、焦虑、重复的话；不减字号、对比度和必要信息。安静来自秩序与留白的节奏，不来自浅灰小字。（守）
- **真实是第一视觉资产。** 纪实摄影里正在发生的人与关系、具体的人说过的具体的话、准确的日期地点和数字，比色彩和装饰更能区分轻生活。缺真实素材时由排版和文字承担，不用图库、AI 人物或无关图补位。（守）
- **东方生活方式 × 编辑设计**，落在：有疏密的竖向节奏、不对称的版心与留白、少量衬线作为「说话的声音」、按主体裁切的照片。它不是宣纸纹理、毛笔字、禅石、绿叶图标。
- **温度来自具体，不来自形容词。** 一个人回来的理由、导游的一句提醒、一张正在笑的脸，胜过「温暖」「治愈」「美好」。
- **成年人的平视语气。** 不制造焦虑、不说教、不承诺疗效，尊重用户自己判断。（守）
- **透明与信任同样重要。** 真实活动安排（包括限制性饮食）、适用条件和风险，在用户做决定的位置要和主动作一样容易看到，不藏进小字、折叠或页尾注释。（守）

**辨识度从哪里来。** 纸色、墨色、深绿加衬线标题，本身是生成式设计最常见的默认组合；只靠它，页面会像任何一个生活方式品牌。辨识度必须来自真实摄影、品牌自己的词汇（轻友、清体营、导游、「慢下来、静下来、放下来」）、可识别的构图签名（见 [visual-language](references/visual-language.md)），以及只有轻生活能说的事实。自检：遮住 Logo 和品牌名，这一屏还认得出是轻生活吗？

## 2. 可读性与真实底线（守）

大量轻友是中年及以上用户，在手机上单手阅读。以下是 375px 下限，不是目标值：

- 叙事正文 ≥16px，行高 1.75–1.9；功能正文 ≥15px；影响判断的事实（日期、地点、价格、状态、风险、身份说明）≥14px；12–13px 只给可有可无的注记。
- 正文对比度 ≥7:1，辅助文字 ≥4.5:1；状态不只靠颜色区分。
- 可点区域 ≥44px；主要动作在其所在屏内可发现；固定栏不遮挡末项与安全区。
- 一页的字号角色不超过 6 个（字阶见 visual-language）。
- 事实、人物、引语和统计口径以 Context / Brief 为准，设计不改写含义；健康表达不涉疗效、排毒、停药。
- **邻接即指认。** 照片紧挨某人的故事，读者就认为照片里是此人。图注纠正不了这种误读：换图、拉开，或不用图。
- 未确认的素材授权、日期、跳转标为「待确认」，不在稿中伪装为真。

下限适用于新设计和获授权修改的页面；已冻结样板不因此自动重开，下次修改时补齐。

## 3. 先定角色，再定形式

动手前用三句话写出页面角色（写在方案里，不写进界面）：

1. **来的人**：谁，从哪里来，带着什么问题（被转发进入 / 老轻友查期次 / 报名途中）。
2. **带走什么**：离开时新知道了什么、感到什么、完成了什么。
3. **表达重心**：叙事、决策还是任务。复合页面按模块分别判断。

角色矩阵见 [page-roles](references/page-roles.md)；矩阵里的比例描述表达重心，不是图片或文字面积。

| 重心 | 设计的主要工作 | 好的样子 |
| --- | --- | --- |
| 叙事 | 组织情绪与证据的递进 | 有起伏、有一个高点、每段带来新东西；可以大胆 |
| 决策 | 让事实可比较、可信 | 事实易扫描，图片与事实互证，感受作辅助 |
| 任务 | 让当前对象、状态、下一步清楚 | 紧凑、连续、可恢复；不强加开篇大图或文学标题 |

已有待办、报名或记录时，任务先于品牌开场。先降低次要内容的权重，再考虑加强主焦点。

## 4. 叙事与节奏

叙事和决策页面，先写**节奏谱**再画稿：按滚动顺序列出每段的「回答的问题 · 新增的信息 · 构图语法 · 强弱」。用它检查：

- **一个高点。** 全页只有一处情绪或视觉顶点，其余段落为它铺垫或收束。高点通常是真实的人和他的原话，而不是数据或口号。
- **每段有增量。** 每滚动一段，用户得到一个新事实、新人物、新画面或新判断依据。删掉后整页不缺什么的段落，就删除或合并。相邻段落不说同一观点的同义句。
- **相邻不同构。** 连续两段不用同一种构图语法（例如都是「标题＋说明＋图＋列表」）。变化手段：尺度（满幅 / 小图）、密度（一句话独占 / 紧凑事实）、方向（左起 / 内收 / 出血）、媒介（摄影 / 纯文字 / 数字）。
- **张弛交替。** 叙事段可以疏、慢、大；事实段要紧、清楚、可扫。不要全页一样「安静」，也不要全页一样大声。
- **标题连读。** 只读各段标题，应能连成一条有推进的线索。换成任何养生品牌仍成立的标题，就太泛了。
- **落在可做的事上。** 叙事最后落到真实可用的下一步，并与透明信息相邻。

任务页同样有节奏，目标是少停顿：当前状态 → 关键事实 → 动作 → 出错后的恢复。

## 5. 跨页面：一条旅程，不是几张好看的页

几个页面属于同一旅程（如 首页 → 认知转化页 → 清体营详情 → 报名）时：

- **先写旅程分工。** 每页回答哪个问题、哪项证据首次出现在哪里。前页预告，后页展开，不重讲。
- **素材账本。** 每张主图在旅程中只有一个主场。再次出现时必须承担不同职责、尺度明显不同，且不邻接与其身份不符的叙述。首屏图和故事高点图不在相邻页重复。
- **语言账本。** 品牌核心语（慢下来、停下来、关心自己、相聚）每条只在旅程里被一处「主讲」；别处用更具体的事实或场景代替。
- **亲缘而不克隆。** 页面之间共享字体角色、色彩语义、动作层级、图片处理和语气，不共享构图模板。好的旅程像同一本刊物的不同栏目。

旅程表与账本模板见 [brief-template](references/brief-template.md)。

## 6. 自由区

以下由设计者决定，方案中说明理由即可：

- 版式与网格、不对称程度、版心偏移、出血方向与尺度对比。
- 在素材账本内选哪张图、怎么裁、给多大，或这一段不用图。
- 段落转场：留白、细线、色场（一页可用一次深绿或深纸色色场作强调）、满幅图。
- 衬线用在哪里、用多大；数字如何成为视觉元素。
- 首屏标题与未定文案的改写提案（并保留旧稿对照）。
- 一处有意义的动效，以及是否需要它。
- 叙事页可以给 2–3 个结构真正不同的方向；任务页给一个方案即可。

每个叙事页面至少有一个只属于它的构图决定，并能说出它为什么属于这一页。大胆花在一处，其余保持安静。

## 7. 视觉语言

字体角色与字阶、色彩角色、签名构图、摄影职责与素材现状、容器与分隔、动效、品牌词汇，见 [visual-language](references/visual-language.md)。摘要：

- 一致性体现在字体角色、色彩语义、动作层级与反馈；不要求相同 Card、间距、密度或构图。
- 容器只用于确有边界的对象和核对组；不在页面上套 Card，也不给每个字段套 Card。
- 默认静态。动效回应用户操作或说明变化；自动轮换可暂停、可手动，尊重减少动态效果的系统设置。

## 8. 文案

- **功能文字做减法。** 逐句问：删掉后，用户还能正确理解并完成任务吗？能就删。标题说过的事，下面不再说一遍。
- **叙事文字做具体化。** 不是删到只剩口号，而是把抽象句换成具体的人、时间、动作或原话。
- 用户原文、真实故事、必要规则以及隐私、费用、风险说明不属于删减对象，精简时不改变含义。
- 统一词汇：清体营（不写轻体营）、轻友、导游。按钮写清点下去会发生什么。
- 警惕模板腔：每段都有眉题、「A · B · C」式元信息串、内容并非序列却用 01/02/03、每个链接后都挂箭头。

## 9. 工作方式

1. **读现状**：当前工作树代码、已验收样板、可用素材及其授权；把 Brief 的已确认与待确认分开。
2. **写设计读取**：页面角色三句话、节奏谱；涉及多页时加旅程分工和账本。
3. **出方案**：先用低保真结构（线框或 ASCII）比较节奏，再做 375px 高保真。
4. **审稿**：用 [quality-review](references/quality-review.md) 自审；至少看一次首屏和完整长图，按影响排序修正最重要的 3–5 个问题，再截图复核。
5. **落地验收**：进入小程序实现时，按 [implementation-acceptance](references/implementation-acceptance.md) 完成状态、数据、截图与回归闭环。

需要改变业务流程、权限与隐私、数据含义、接口契约或已确认产品决定，或真实素材与授权缺失导致主方案不成立时，暂停受影响部分并提交具体决策；其余设计判断自主完成。

**何时停止。** 任务页：主要任务清楚、关键状态完整、没有新增问题。叙事页：审稿无阻断项，节奏谱只有一个清楚的高点，跨页账本无冲突——然后交给用户评审。冻结样板只因明确问题或新的授权重开。
